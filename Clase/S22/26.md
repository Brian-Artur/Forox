# CORS   

**CORS** (Cross-Origin Resource Sharing) es un mecanismo de seguridad implementado por los navegadores que permite o restringe las **peticiones HTTP entre diferentes orígenes** (dominios, protocolos o puertos). Su propósito es **proteger a los usuarios de ataques como el Cross-Site Request Forgery (CSRF)** o la exposición involuntaria de datos sensibles.

## 🔒 ¿Por qué existe CORS?

Por defecto, los navegadores aplican una política de **Same-Origin Policy (SOP)**, que impide que un sitio web acceda a recursos de otro origen por seguridad.

Pero hoy en día, muchos sitios web necesitan **consumir APIs desde otros dominios** (por ejemplo, un frontend en `localhost:3000` llamando a un backend en `api.midominio.com`). CORS permite hacer esto, **siempre que el servidor remoto lo permita explícitamente**.
### 📡 ¿Cómo funciona CORS?

Cuando el navegador detecta que estás haciendo una **petición a un origen distinto**, envía una **petición previa opcional** llamada `preflight request`, que es una solicitud `OPTIONS`. Esta sirve para preguntar al servidor si permite esa operación.

El servidor debe responder con cabeceras como:
```http
Access-Control-Allow-Origin: https://midominio.com
Access-Control-Allow-Methods: GET, POST, PUT
Access-Control-Allow-Headers: Content-Type, Authorization
```

### 🧪 Ejemplo: flujo de CORS

1. Desde el frontend:
```js
fetch('https://api.otroservidor.com/datos', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer token123'
  },
  body: JSON.stringify({ name: "Juan" })
});
```

2. El navegador detecta un **origen cruzado** y envía primero:
```http
OPTIONS /datos HTTP/1.1 
Origin: https://miweb.com 
Access-Control-Request-Method: POST 
Access-Control-Request-Headers: Content-Type, Authorization
```

3. El servidor responde:
```http
HTTP/1.1 204 No Content 
Access-Control-Allow-Origin: https://miweb.com 
Access-Control-Allow-Methods: POST 
Access-Control-Allow-Headers: Content-Type, Authorization
```

4. Si todo es correcto, el navegador hace la **petición real**.    

---

### ⚙️ ¿Y en Express?

Puedes configurar CORS fácilmente usando el middleware [`cors`](https://www.npmjs.com/package/cors):

```bash
npm install cors
```

```ts
import express from 'express';
import cors from 'cors';

const app = express();

app.use(cors({
  origin: 'https://miweb.com', // o ['https://a.com', 'https://b.com']
  methods: ['GET', 'POST', 'PUT'],
  allowedHeaders: ['Content-Type', 'Authorization']
}));

app.get('/datos', (req, res) => {
  res.json({ mensaje: 'CORS funcionando' });
});
```


---

### ⚠️ Consideraciones de seguridad

- Nunca uses `origin: '*'` si estás enviando **cookies o tokens sensibles** (`credentials: include`), ya que se bloquea automáticamente. 
- No expongas más métodos o cabeceras de los necesarios.   
- Controla bien los orígenes permitidos si tienes datos sensibles.
