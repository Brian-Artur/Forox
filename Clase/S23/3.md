## 📘 ¿Qué hace DDL?

DDL incluye las sentencias SQL que se usan para **crear, modificar o eliminar estructuras de la base de datos**, como:

|Sentencia|Qué hace|
|---|---|
|`CREATE`|Crea bases de datos, tablas, índices, vistas...|
|`ALTER`|Modifica la estructura de una tabla existente|
|`DROP`|Elimina tablas, vistas, bases de datos, índices|
|`TRUNCATE`|Vacía una tabla rápidamente, sin `WHERE`|
|`RENAME`|Cambia el nombre de una tabla o columna|

---

## 🛠 Ejemplos

`CREATE TABLE personas (   id INT PRIMARY KEY,   nombre VARCHAR(100) );`

`ALTER TABLE personas ADD COLUMN edad INT;`

`DROP TABLE personas;`

---

## 🧠 Comparación con otros tipos de lenguaje SQL

|Tipo|Qué controla|Ejemplos|
|---|---|---|
|**DDL**|Estructura de la base de datos|`CREATE`, `ALTER`|
|**DML**|Manipulación de datos|`INSERT`, `UPDATE`|
|**DCL**|Control de permisos|`GRANT`, `REVOKE`|
|**TCL**|Control de transacciones|`COMMIT`, `ROLLBACK`|


## Significado de RESTRICT en actualizaciones (UPDATE)

Cuando una clave foránea tiene la opción **RESTRICT en UPDATE**:

1. **Bloquea la modificación** del valor de la clave primaria en la tabla referenciada (en este caso, `personas.persona_id`) si existen registros relacionados en la tabla hija (`personas_relacionada`).
    
2. **Comportamiento práctico**:
    
    - Si intentas actualizar el `persona_id` en la tabla `personas` mientras existan registros en `personas_relacionada` que hagan referencia a ese ID, MariaDB/MySQL **rechazará la operación** con un error.
        
    - Es más estricto que `NO ACTION` (aunque en la práctica son equivalentes en MariaDB/MySQL).
        
3. **Diferencia con otras opciones**:
    
    - **CASCADE**: Actualiza automáticamente el ID en todas las tablas relacionadas.
        
    - **SET NULL**: Establece NULL en las referencias (requiere que la columna acepte NULL).
        
    - **NO ACTION**: Similar a RESTRICT en MariaDB/MySQL.

## ¿Cuándo usar RESTRICT en UPDATE?

Es útil cuando:

- Quieres garantizar que **nunca** cambien los IDs de las personas una vez creados.
    
- Prefieres manejar manualmente las actualizaciones de IDs en todas las tablas relacionadas.
    
- Tu diseño considera los IDs como valores inmutables.
